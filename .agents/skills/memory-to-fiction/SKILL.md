# memory-to-fiction

把 memory 蒸馏出的个人特征转化为 fiction 的创作素材。单向管道：只读 memory，不写回。

## 时机

接到具体创作任务时加载（写场景、立人物、开新章、开书前的同构检查）。不随 profile 更新自动执行——创作有节奏，素材按需取。

## 源

`assets/memory/profile/` 下五轴档案：

| 轴 | 文件 |
|---|---|
| 情绪 | `emotions.md` |
| 价值观 | `values.md` |
| 触发点 | `triggers.md` |
| 方法论 | `methods.md` |
| 表达 | `expressions.md` |

路径以主仓库根为基准。fiction 单独克隆、无主仓库结构时，用环境变量 `QTFOUNDER_MEMORY_PATH` 指向 memory 仓库（沿用 qtfounder 数据源惯例），从其 `profile/` 读取。

## 步骤

### 1. 选轴

按任务类型取对应轴，只取所需，不整包灌入：

| 任务 | 取材轴 |
|---|---|
| 写场景、内心戏 | emotions |
| 设计冲突、压力、崩溃点 | triggers（+ values 提供对立立场） |
| 立人物、道德困境 | values |
| 写人物解决问题 | methods |
| 开书前 / 改稿后检查 | expressions（仅检查，不取材） |

### 2. 转化

核心是主体转换：profile 是关于"我"的，素材是关于"角色"的。直接复制即失败。

| 轴 | 产出 | 变换规则 |
|---|---|---|
| emotions | 场景情绪底色 | 我的感受 → 角色内心；**情绪逻辑保留，事件替换为虚构** |
| triggers | 情节压力装置 | 我的诱因 → 外化为事件（睡醒千头万绪 → 角色的清晨危机） |
| values | 人物道德脊柱 | 我的判断线 → 角色立场；可正置（认同）可反置（对抗） |
| methods | 人物思维习惯 | 我的框架 → 角色的分析习惯；选择可以与我不同 |
| expressions | 同构检查结论 | 元层面：这次是复用作者签名，还是刻意破除？给结论与理由 |

素材写成散文，不写成结构化卡片；剥离真实人物、真实项目名与真实事件，只留情绪逻辑与判断结构。

### 3. 落盘

| 产出 | 位置 |
|---|---|
| 已绑定小说的场景 / 人物素材 | `assets/fiction/<小说>/2_场景/`，命名 `素材-<主题>.md` |
| 未绑定或跨书素材 | `assets/fiction/草稿箱/4_场景素材/`（首次使用时创建） |
| expressions 检查结论 | 对应小说根目录的 `decision.md`（创作决策记录），不单独建文件 |

## 防错

- **不按日期、不一对一**：按任务选轴，多对多；一条情绪可服务多个场景，一个场景可拼多轴。
- **不混业务**：roadmap 与日志中的工程/组织内容不是创作素材。roadmap 的核心问题/元目标若提炼为**主题**，显式标注"推断自 roadmap，非日志证据"。
- **不回流**：`草稿箱/2_情绪日记` 曾是 profile 的体裁参照；本 skill 的产出不得作为 profile 蒸馏的证据——单向管道。
- **保留标注**：expressions 中标注"推断"的条目，引用时保留标注。

## 验证

首次跑通、或改过流程后，用真实写作任务验证：

1. 挑一个真实场景任务，走流程产出 1-2 份素材。
2. 自问：拿到素材知道怎么下笔吗？
3. 限时 30 分钟写 500 字初稿。
4. 对照：不走 skill、直接从日志原文取材，同样条件再做一次。

结果写入 `assets/fiction/实验室/`（命名 `YYYY-MM-DD-<任务>.md`）。通过后在 fiction 的 `AGENTS.md` 挂载触发说明；不通过则记录卡点作为下次修订输入。实验记录不写入归档站——`assets/archive` 只做历史归档，不承担业务用途。
